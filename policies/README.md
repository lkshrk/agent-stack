# policies

Policies for other workloads: PR-Agent fetches its files from this repository at runtime, and the Omnigent package is baked into the Omnigent images.

| Path | Consumer |
| --- | --- |
| `pr-agent/pr-agent.toml`, `pr-agent/review.md` | The PR-Agent init container in h-cloud (`kubernetes/apps/ai/pr-agent`) fetches both from `main` at pod start and merges `review.md` into `extra_instructions`. Repository-local overrides remain possible |
| `omnigent/` | Omnigent policy package baked into the server and runner images |

## Omnigent shell gates

`no_merge`, `no_nested_agents`, `path_guard`, `docs_vcs`, `read_only_shell`, `git_verbs` and `no_secret_reads` share one parser and command resolver (`agent_stack_policies/_shell.py`). It walks `sh -c`/`bash -c` (and the other shells), `eval`, `$(…)` and backtick bodies, process substitutions and here-strings into a shell, and strips leading keywords, `VAR=` assignments and the wrappers `env` (including `-S`), `command`, `builtin`, `exec`, `nohup`, `setsid`, `ionice`, `nice`, `timeout`, `flock` (and `flock -c`), `stdbuf`, `time`, `xargs`, `find -exec`/`-execdir`/`-ok`/`-okdir`, `sudo`, `doas`, `su -c`, `script -c`, `watch`, `parallel`, `npx`/`bunx`/`pnpx`, `pnpm dlx`/`pnpm exec`, `yarn dlx`/`yarn exec`, `npm exec`/`npm x`, `bun x`, `uv run`, `uv tool run`/`uvx` and `mise exec`/`mise x` (`--` or `-c`). `no_nested_agents` also denies a script piped into a shell (`| sh`, `bash -s`, `bash < file`) and commands piped into `parallel`, and exempts only each CLI's own help and version flags (`codex -V`, `claude`/`omp`/`opencode -v`).

`read_only_shell` is an allowlist for report-only agents: read commands (`rg`, `cat`, `head`, `sed -n` line ranges, git read verbs and similar, `gh` reads with `extra_commands: [gh]`), no `VAR=` or `env VAR=` assignments, no token containing `>` other than `>`/`>>` into `/dev/null`, no `find -delete`, `sort -o`/`--compress-program` or `rg --pre`, and `exact_commands` allowed verbatim. The planner, its critic and Polly's Codex worker run under it. `git_verbs` limits git to read verbs plus `extra_verbs`; Polly gets `fetch` and `worktree`. With `allow_only`, `path_guard` enforces the scope for the file and patch tools and, best-effort, for the shell: redirect targets (`>`, `>>`, `<>`, `&>`, `&>>`, `>|`, `>&`), `tee` files, `sed -i`/`--in-place` files, `cp`/`mv`/`install`/`ln`/`rsync` destinations (including `-t DIR`, `-tDIR`, bundled `-rt DIR` and `--target-directory`), `mv` sources, `touch`/`rm`/`rmdir`/`truncate`/`mkdir`/`chmod`/`chown`/`chgrp` targets and `dd of=` outside the scope are denied. `/tmp`, `/tmp/…` and `/dev/null` are always allowed; any other absolute, `~` or `..` target, and any target that needs `$`, backtick or brace (`{a,b}`, `{1..3}`) expansion, is denied. Quoted operator words (`'<'`) are read both as literals and as operators, because `eval`, `watch` and `parallel` join them back into a shell string. `exempt` only lifts a `deny` match and never widens `allow_only`, and an unparseable shell command is denied whenever `deny` or `allow_only` is set. Not covered: a relative path after `cd`, files that other commands write (`sort -o`, `git diff --output`, compilers, a build or test command), an expansion in another operand that produces the target (`cp {/tmp/a,src/a}`), abbreviated GNU long options (`--target=`, `sed --in-pl`) and globs such as `.?` that match `..`. Process substitution bodies (`<(…)`, `>(…)`) are walked as statements by every gate. `read_only_shell` takes bare command names only, allows no wrapper except `command` and `find -exec` (no shell through `find`), and allows only the stderr redirects `2>/dev/null` and `2>&1`. It also denies variable-assigning builtins (`printf -v`, `read`, `mapfile`, `declare`, `export`, `let`, `getopts` and the like), `test -v`, and arithmetic, subscript, substring and indirect expansions (`$((…))`, `((…))`, `$[…]`, `${x:…}`, `${a[…]}`, `${!x}`). `git_verbs` denies any variable assignment in a command that runs git, and `no_merge` denies a variable in a push or merge. A `${…}` with `:`, `[`, `@` or `!` after the name (substrings, subscripts, `@P`/`@E`/`@Q`/`@A` transformations, indirection) is opaque: `read_only_shell` and `git_verbs` deny it outright, and `no_merge`, `no_nested_agents` and `docs_vcs` deny it when the command mentions git, gh or an agent CLI or names an opaque command, and always for the decoding `@P`/`@E`. Every gate that walks `-c` bodies denies positional arguments after the body. `no_merge` and `git_verbs` deny `xargs`/`parallel` into a git push or gh merge, or into git, because stdin can supply arguments. `no_merge` also denies `gh pr merge`, `gh api` merge routes and GraphQL merge mutations, force-pushes, tag and other non-branch ref pushes (`--tags`, `--follow-tags`, `--all`/`--branches`, `--mirror`), pushes to a protected branch, and any push without an explicit destination it can check (no refspec, or a bare `HEAD` or `@`); the remedy is `git push origin HEAD:<branch>`. It finds `push` after git's global options, using the git 2.47 and 2.56 table (`-C`, `-c`, `--config-env`, `--git-dir`, `--work-tree`, `--namespace`, `--attr-source` and `--shallow-file` take a separate value); any other long global option without `=` is denied when the resolver finds the git command, or when an unresolved `git` word is followed by `push`, `merge` or `config`, so a newer value option can't shift the arguments. It reads push options as git does: short clusters (`-uo X`), unique long-option prefixes (`--force-w`, `--push-opt`) and the options that take a value (`-o`, `--push-option`, `--repo`, `--receive-pack`, `--exec`, `--recurse-submodules`); an ambiguous prefix is denied, and `--` or `--end-of-options` ends the options. It checks `-c`, `--config-env`, `GIT_CONFIG_*`, `GIT_CONFIG_PARAMETERS` and `git config <key> <value>` writes for config that can redirect a push or merge: `alias.*`, `push.*`, `url.*`, `include.*`, `includeIf.*`, `remote.pushDefault`, `remote.<name>.push`/`url`/`pushurl` and `branch.<name>.merge`/`remote`, plus pointing git at another config file (`GIT_CONFIG`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`).

The gates read tokens, not a running shell. A command named through a variable (`$G push`), an alias written into a config file git loads (a hand-edited `.git/config`, a `git config <key> <value> get|list` value-pattern write, `git config --rename-section`, or a `.gitconfig` under another `HOME` or `XDG_CONFIG_HOME`), a copied binary or a launcher outside the list above (`ssh`, `chroot`, `docker exec`) is not resolved, and neither is a relative path after `cd`. Branch protection and the GitHub token scopes are the backstop.

The shell gates also don't see code that is decoded at runtime (`printf '%b' … | bash`, `$'\x67it'`, `source <(…)`) or put in a script file and run (`bash s.sh`, `make push`). For those, GitHub-side protection and Plan 3's post-run ref check are the boundary.

`no_secret_reads` (security-review) denies shell words naming `/agent-secrets`, other than the `GH_TOKEN_FILE=… gh` form, and the gh commands that print the token. It does not see paths built inside an interpreter (`python3 -c`, `node -e`, `awk`), reached by filesystem search (`find / … -exec cat`, `grep -r . /`), named relative to `/` after `cd /`, or matched by a glob that isn't normalised first (`/tmp/../agent-secret?/…`), so the read-only scope of the review token is the boundary.
