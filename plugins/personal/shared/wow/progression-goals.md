# Plan progression without inventing achievement credit

Use this branch for quests, reputation, professions, items, attunements, leveling milestones or supported Forever Legacy goals when the request is not a native achievement/AP plan. It replaces achievement-only ranking, schema and totals; retain the skill's source research, freshness, language, timing, repeatability, output-destination and preservation rules. A supported achievement request continues through the ordinary achievement workflow.

Resolve game context first. For personalized remaining work, use current supported observations or an explicitly chosen dated/user-reported fallback. If those are missing, ask for the smallest necessary state check and continue independent mechanics research. Generic plans remain conditional, with prerequisites visible; do not claim they describe the player's actual remaining work.

Keep one canonical checklist in a Markdown note, also usable in Obsidian. Retain existing task IDs and checkmarks; use stable goal IDs for new records, separate from game entity IDs. Each goal identifies its type, verified entity/source, executing character, starting/target progress where known, remaining steps, prerequisites, expected result, and completion check. Separate observed, user-reported and unknown progress. Do not fill unknown quantities with zero.

Order actions by useful progress toward the requested goal, prerequisites and shared travel. Include reasonable time ranges, source dates, current access, repeatability/reset limits, materials/costs and a clear stop/resume point. Show verified version-specific entity links and supported waypoints. Quick wins, buyable, grindable, long-term and help-needed categories still apply when they describe actual work; self-found or other restrictions can make purchases/transfers inapplicable.

For a duo, establish each player's game/environment, compatible world/ruleset/faction, progress and available characters separately. Show who benefits, who performs each action, whether credit is shared/individual, and whether repeats or separate items are required. Include useful one-player detours with their cost. Preserve per-player completion; a shared checkbox does not prove both earned credit.

For a static dashboard or index, show next actions, known goal progress, completed/history links, shopping allocations, access checks and source dates. Sum only compatible units with the same scope. Keep reputation, profession skill, quest completion, collections and Legacy earnings separate. Do not display invented account AP, AP/minute or meta rewards. For Forever, distinguish account/ruleset Legacy earnings from each character's selected perks; do not assume a conventional achievement schema represents either.

Do not load the achievement Dataview model, generate `ach-N` anchors for these goals, or put non-achievement records into achievement purchase allocations. Use ordinary Markdown headings/checklists and tables instead; a general goal UI is not required to deliver the plan. For mixed requests, link the native achievement dataset to the separate goal checklist rather than mixing their totals. Update existing records in place and preserve manual history on every refresh.
