# Required data refresh before planning

Before selecting, ranking, routing or estimating personalized work, **attempt to update the local account database from the current configured source**. This applies to new plans, replacement lists, next-session recommendations and duo plans; an existing dataset or checklist is not a reason to skip the attempt. Reuse a verified refresh already completed for the same request rather than collecting it twice.

Read the private setup record and current environment documentation to find the working reader/transport. Retrieve complete current exports, validate account identity, source modification times and per-field scan clocks, then merge valid observations into the local database while preserving manual progress and older fields not covered by the import. Read back the saved result and record the refresh outcome/source dates before planning. A successful download of stale cached data is not proof of current state.

Resolve game/environment before choosing a reader or merging. Keep version-specific observations isolated; do not use a Retail adapter for another game merely because the addon filename or character GUID matches. If the needed system/reader is unsupported, explain that capability gap once and ask for a compatible export or the user's explicit choice to plan from current user-reported state. Record that state as user-reported with its date and limits, not an API-confirmed refresh. Do not repeatedly request an unsupported scan or block general sourced instructions that make no personal eligibility claim.

An explicit instruction to use supplied current state already establishes that choice. Keep it scoped to the stated game/character and do not ask for approval again. Resolve material contradictions in the report rather than upgrading it to machine-verified evidence.

**If the refresh fails, required coverage is missing, or freshness cannot be established, stop the dependent planning and ask the user for help/advice.** State the source/reader tried, concrete error or stale/conflicting dates, and the smallest useful question: has the access method changed, where is the current source, or does the game/export need saving or syncing? Do not ask for passwords in chat. Do not silently substitute an old snapshot, public cache, manual checkmarks or a generic plan. Keep the previous database and guide intact. Continue independent source/method investigation while awaiting the answer, but resume personalized planning only after a successful verified refresh or the user's explicit choice of dated older/user-reported state with its limitations.

Pure formatting, file organization or an explicitly presentation-only dashboard update can retain dated existing data when no new gameplay recommendations are generated; do not describe that as an account refresh.
