# bundles

Omnigent agent bundles. `images/omnigent-server/Dockerfile` copies this directory to `/agents/` in the server image, and the server starts with `--agent /agents/polly --agent /agents/planner`. `security-review` and `documenter` are in the image but not registered yet: security-review waits for per-bundle GitHub tokens (Plan 2 Task 11b), the documenter for read-only startup files and launch configs in runner pods (Tasks 11c and 11d).

| Bundle | Contents |
| --- | --- |
| `polly/` | Orchestrator adapted from Omnigent's example. It writes only `.polly/registry.json`, `.polly/diffs/` and its own skills (denied outside them for the file and patch tools, best-effort for the shell), and runs no mutating git verbs or pushes. `config.yaml` holds its instructions and tools, `agents/claude_code` and `agents/codex` the workers, `skills/` the skills `cross-review`, `fanout` and `investigate` |
| `planner/` | Read-only planner. `config.yaml` holds its instructions, the `code_graph` and `result_check` (`agent_stack_policies.mcp`) MCP servers and its policies (no writes, no pushes, GitHub read-only, at most 3 critic dispatches, validated final result), `skills/` the skills `plan-architect`, `plan-decompose` and `plan-contract`. `agents/critic` is the separate read-only critic on `claude-sdk` with `anthropic-auto` and the skill `plan-critic`: it grades each draft and returns findings and the coverage map, and the planner revises. A planner session spans several turns: its result is the first turn-final response carrying a ```json block, which `result_contract` has validated; earlier turns are interim, a consumer never reads a block from a non-final segment, and a consumer timeout or an idle session without a result counts as `BLOCKED{environment}` |
| `security-review/` | Read-only security reviewer on `codex-native` with `openai/gpt-astra`. `config.yaml` holds its instructions, the `result_check` (`agent_stack_policies.mcp`) MCP server and its policies (the planner's read-only set plus Codex's `apply_patch` and `spawn_agent` denied, a best-effort `secret_files.no_secret_reads` gate that denies shell mentions of `/agent-secrets` other than `GH_TOKEN_FILE=/agent-secrets/github/review gh …` and the `gh` commands that print or hand out the token, validated security result), `skills/` the skill `security-audit`. Sessions need `terminal_launch_args: ["--profile", "security-review"]`, which selects the runner image's read-only Codex profile `images/omnigent-host/codex/security-review.config.toml` |
| `documenter/` | Docs-only documenter on `claude-sdk` with `anthropic-auto`. `config.yaml` holds its instructions, the `result_check` (`agent_stack_policies.mcp`) MCP server and its policies (file-tool writes limited to docs paths with the forbidden paths still denied, shell writes outside them denied best-effort, commits limited to doc paths by the `docs_vcs` allowlist (a guardrail; Plan 3's post-run diff check is planned, not built), pushes without force, no merges, no Linear, validated documenter result), `skills/` the skills `docs-delta` and `docs-audit` |

Plan 3's Hermes session tool (planned, not built yet) will create one `gap` sub-issue per gap from the validated planner, security-review and documenter results, blocking the parent issue. Implementer gaps travel in the PR description under `## Gaps` until Plan 3 adds Polly's result contract. Workers never create the sub-issues.
